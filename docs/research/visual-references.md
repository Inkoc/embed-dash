# Visual references for the app chrome

Research snapshot: 27 November 2026. The links point to product interfaces or documented interface examples, not endorsements of every screen or brand treatment. Observations are design cues from the linked material; validate them in a visual design pass. The message preview itself should reproduce Discord's chat appearance as accurately as practical; the surrounding editor, navigation and picker can have their own identity. The existing `assets/icon.svg` is a white ED monogram in a rounded teal `#0d9488` square: use teal sparingly as the app's primary accent, with contrast checked for text and focus indicators.

1. **[Ghost — publishing and preview](https://ghost.org/help/publishing-content/)**. The publishing workflow places preview and publishing actions at the top and presents the content as the central object, with preview modes for different outputs. The restrained, reading-oriented hierarchy and purposeful whitespace are useful for a composer. **Transfer:** keep a clear editor/preview relationship and place send, schedule and preview context in a consistent action bar, with secondary options revealed only when needed.
2. **[Penpot — workspace interface](https://help.penpot.app/user-guide/first-steps/the-interface/)**. A design canvas is framed by purposeful tool areas and panels; controls are organized around the current task rather than a dashboard of unrelated cards. **Transfer:** use a stable working surface with a clearly bounded live preview and a compact inspector-like form. Let the panes stack on narrow screens without losing the preview's identity.
3. **[Are.na — channels](https://help.are.na/docs/getting-started/channels)**. Collections use a simple block-and-channel vocabulary and sparse, line-based organization. Its [interface history](https://www.are.na/editorial/are-nas-new-web-client-sander-is-now-available-for-everyone) also shows light and dark views and resizable panels. **Transfer:** distinguish server group headings, channel rows and selection counts through spacing and rules; let content carry the visual weight rather than nested containers.
4. **[Raycast — search bar](https://manual.raycast.com/search-bar)**. Search is the immediate focus, with a compact result list and deliberate keyboard flow; the [action panel](https://manual.raycast.com/quickstart) exposes contextual actions. **Transfer:** make the channel picker searchable on opening, show a strong active row and selection state, and support keyboard navigation without hiding the ordinary visible controls. Borrow the interaction density, not the launcher window's visual effects.
5. **[Craft — interface and block formatting](https://www.craft.do/learn)**. Its documented editor separates navigation from the writing surface and uses block formatting to keep controls close to the content. The [colour and picker update](https://www.craft.do/pt-BR/blog/craft-update-3-6-0) illustrates careful treatment of editing controls. **Transfer:** use readable type, measured spacing and contextual controls for embed fields; expose labels and limits while keeping optional fields calm until expanded.
6. **[Are.na Editorial — Interface](https://www.are.na/editorial/interface)**. This curated editorial index juxtaposes varied interface examples under plain, prominent titles; the typographic hierarchy and simple vertical sequence make it easy to scan disparate material. **Transfer:** use a quiet editorial hierarchy for templates and history: clear titles, meaningful metadata, restrained separators and room for the content to differ instead of identical promotional tiles.

## Possible directions

- **Editorial workbench** — Ghost + Are.na Editorial. Warm off-white chrome, near-black text, a confident heading weight and thin rules; teal reserved for selected controls and the main action. A generous editor column and independently bounded preview create a publication-like workspace. History becomes a readable list with dates and outcome labels.
- **Studio instrument** — Penpot + Craft. Neutral light surfaces, subtle panel boundaries, a compact toolbar and carefully spaced field groups. Use the teal mark as a small anchor in navigation; reserve stronger contrast for focus, selection and validation. Short transitions clarify panel changes, with reduced-motion support.
- **Quiet command desk** — Raycast + Are.na channels. A denser, typography-led layout with a visible search field, crisp selection rows and keyboard hints alongside conventional controls. Teal identifies the selected state; server groups use spacing and rules instead of nested cards. The preview remains visually distinct from this utilitarian shell.

Across directions, retain explicit field labels, accessible contrast, visible focus, legible hierarchy, responsive stacking and an accurate preview. Avoid decorative gradients, glow, glass, repeated icon-led cards, excessive shadows and extra accent colours. Use motion to explain changes in state, not as ambient decoration.
